# FocusOn 第一版设计

状态：已确认。用户于 2026-10-09 确认完整设计可作为第一版开发依据。本文是设计与验收依据，尚未实现采集程序。

## 目标与范围

为个人的一台 Windows 11 电脑，自动记录每天各软件的前台使用时长和切换过程。数据保存在本机，离线可运行。

第一版提供日期选择、当天各软件时长汇总、使用时间条、按时间排列的日志列表和记录详情。所有前台软件按相同规则记录，包括 FocusOn 自身；后台音乐和未激活的另一个屏幕上的窗口不累计软件使用时长。

第一版不采集截图、网页正文、键盘输入内容或浏览器 URL，不增加跨日检索、导出、软件排除名单、云同步、项目分类或注意力评分。2026-10-10 用户要求的 Harness 截图版 UI 增加当前日期的软件/标题搜索，限定为本地回看筛选。

## 用户已确认的记录规则

每条使用记录包含软件名、窗口标题、开始时间、结束时间和持续时长。

- 前台窗口变化时，结束旧片段并开始新片段。
- 同一前台窗口的标题变化时，也结束旧片段并开始新片段。浏览器切标签页、编辑器切文件和标题自动更新均适用。
- 同一软件的不同片段分别保留，汇总时合并为该软件的累计时长。
- 完整保留短暂切换，包括只有 2 秒的片段。重复的相同窗口与相同标题事件不产生新片段。
- 没有键鼠输入仍然计时，因此静读文章和观看视频可以计入。
- 锁屏、睡眠、灭屏和手动暂停期间停止计时，以有原因的灰色区段呈现。
- 重新解锁且亮屏后自动恢复；手动暂停必须手动继续。恢复时读取此刻的前台窗口，不沿用暂停前的软件。
- 程序未启动、已退出或采集故障期间显示“未记录”，不推测活动，也不补算给此前的软件。
- 跨午夜的片段在每日视图中按日期分开显示，每天只累计落在该日范围内的部分。

“前台使用时长”是前台状态的度量，不能证明人的注意力。离开电脑却未锁屏、灭屏或暂停时，前台软件仍会被计时。

## 界面与交互

2026-10-10 追加要求（10 票，优先于最初布局）：首行输入标题开始独立计时，随后显示累计时长及暂停/继续、停止。三行总览为使用/停止/计时，未记录区间保留在使用行斜纹；默认从当天第一条可确认的记录至最新终点，自动增长，可切换本地全天 24h。缩放/平移保留位置，重置恢复所选模式。标题计时不计入软件汇总，可搜索、查看详情和按天删除。具体行为见使用说明及 ADR 0002。

主窗口保持一个回看页面。

- 短片段保留真实比例，不人为扩大计时宽度；可通过缩放或日志列表查看。
- 日志使用虚拟化列表，显示时刻到秒，详情显示更精细的时长。显示取整不改变统计值。
- 日期、列表选择、详情与缩放按钮可用键盘操作。颜色之外保留软件名、时间和状态文字。

## 运行与本地记录管理

- 登录 Windows 后自动启动，驻留系统托盘；关闭主窗口继续采集。托盘提供打开时间线、暂停／继续、退出。
- 明确退出时结束当前片段并停止采集。重复启动只打开已有实例，不启动第二个采集器。
- 登录自启可能有延迟；启动之前的时间仍显示为未记录。
- 数据长期保存在当前 Windows 用户的本地应用数据目录，默认不自动清理。
- 按天删除明确显示所选日期和删除范围，确认后通过事务删除。跨日数据只删除该日部分，其他日期保留。
- 删除今天时先结束当前开放片段，删除该日已有记录，再从删除完成后的时刻开始新记录，避免后台保存把已删时间写回来。
- 已删除范围显示为没有可用记录，不解释为采集故障、不从旧片段补回。

窗口标题可能含文档名、网页名等私人信息，长期保存和按天删除均适用于这些字段。

## 计时不变量与状态规则

在系统时间连续且时区不变的正常计时范围内，区间统一采用“含开始、不含结束”的规则，相邻片段共享边界，同一时刻最多归属一种状态。使用时长只来自软件片段；停止计时与未记录区间不参与软件汇总。

恢复计时必须同时满足：采集可用、没有手动暂停、会话已解锁、没有处于睡眠、屏幕已亮。任何单个唤醒、解锁或亮屏事件都不能覆盖其他停止条件。

已知停止原因重叠时，采用工程默认显示顺序：手动暂停 > 睡眠 > 锁屏 > 灭屏。主要显示原因变化时分段，这些区段均不计入软件时长。手动暂停标志独立保留，锁屏再解锁不能清掉它。

| 情况 | 计时处理 | 时间线处理 |
| --- | --- | --- |
| 换前台窗口或当前窗口标题变化 | 结束旧片段，开始新片段 | 保留所有片段 |
| 没有键鼠输入 | 继续当前前台计时 | 保留使用片段 |
| 手动暂停、锁屏、睡眠或灭屏 | 结束当前软件片段 | 已知停止原因区段 |
| 所有停止条件解除 | 重新读取当前前台窗口 | 开始新使用片段 |
| 程序未运行或采集不可信 | 不累计软件时长 | 未记录区间 |
| 能确认前台窗口但无法读取软件身份 | 不猜测身份 | 使用片段显示“未知软件” |
| 能读取软件但窗口标题为空或读取失败 | 保留真实使用时间 | 标题显示“标题不可用” |

进程停止前的状态不能延续为整个未运行区间的解释。例如，锁屏时程序崩溃，重启之前的后续缺口不能全部推测成锁屏。

## 建议的最小实现方案

这一节是工程建议，尚未安装依赖或创建程序。

使用 C#、.NET 10 LTS 和 WPF，在当前用户会话内运行一个桌面进程。WPF 原生绘图和列表实现时间条及日志，托盘使用 WinForms NotifyIcon。本地 SQLite 通过 Microsoft.Data.Sqlite 访问，先保持一个项目。

~~~mermaid
flowchart LR
    W[Windows 前台、标题、会话与电源事件] --> R[采集与计时状态]
    R --> D[(本地 SQLite)]
    D --> U[时间条、日志与每日软件汇总]
    T[托盘暂停、继续、退出] --> R
~~~

最少需要三部分职责：读取 Windows 状态、维护并持久化片段、查询和展示每日记录。它们同属一个项目，不引入 Windows 服务、独立后端、浏览器插件、ORM 或 WebView。

### 采集与持久化

- 以 SetWinEventHook 的 EVENT_SYSTEM_FOREGROUND 事件捕获前台切换，读取前台窗口、进程身份与标题；监听当前前台窗口的名称变化。启动与每次恢复也要补读当前状态。
- 事件回调保留接收时刻并顺序交给计时状态处理；避免重入、重复事件和持久化操作阻塞事件接收。保持消息循环和回调委托存活。
- 用低频检查点定时器校核当前窗口及标题，并保存已确认的终点。建议初始周期为 5 秒；它用于补查与保存，不代替前台切换事件。
- 切换、暂停和正常退出时立即保存边界；更新与插入放在同一事务中。
- 异常停止后只保留最后成功保存且可确认的范围，之后显示未记录。检查点之间的未保存活动可能丢失，不将其补给最后一个软件。
- UTC 用于存放起止时刻，本地日期用于回看；持续时长使用单调时钟累计。仅靠单调时钟或采集顺序不能解决系统时间回拨造成的时间轴重叠；第一版不承诺在手动改时钟或切换时区后仍正确裁切历史日期。实施时必须识别此类异常并提示，不静默修改历史；异常时间映射需另行设计和验证。
- 每日边界切片与汇总使用同一范围。删除也按该范围处理，避免跨日数据误删。
- 身份读取失败、空标题和暂无前台窗口有明确回退；前两者保留已知使用时间，后者属于无法确认的范围。
- 数据库写入失败时提示记录异常并停止声称正在可靠记录；恢复后把不可信时间标为未记录，保留已有成功写入的数据。
- 多显示器的灭屏判断以会话显示状态为准；仅关闭一台显示器不直接等同于整个会话灭屏。实现时核验目标硬件上的事件行为。

### 最小数据结构

一个区间表即可，软件汇总由查询计算，不维护独立汇总副本。

| 字段 | 用途 |
| --- | --- |
| Id | 记录标识及采集顺序 |
| Kind | 软件使用、手动暂停、睡眠、锁屏、灭屏或未记录 |
| StartUtc / EndUtc | 起止时刻；当前片段终点为最近确认并保存的时刻 |
| DurationMs | 已确认的持续时长，不依赖墙上时钟相减 |
| AppKey / AppName | 软件身份和显示名称，仅软件片段有值 |
| WindowTitle | 该软件片段的窗口标题，仅软件片段有值 |

已解析的软件身份优先使用规范化可执行文件路径；PID 和窗口句柄只用于当前采集，不作为跨启动的软件标识。软件名可用进程名兜底，无法识别时显示未知软件。打包应用的身份解析需验证，不能把宿主进程误标为实际软件。

### 当前开发环境

只读检查发现本机有 .NET / WindowsDesktop runtime 8.0.6，但没有 .NET SDK，另有 Visual Studio 和 Windows SDK。按此方案实施前需要安装匹配的 .NET SDK。此设计阶段没有安装或修改开发环境。

.NET 10 当前为 LTS，官方支持至 2028 年 11 月。选择 WPF 是本项目对单机后台采集与自定义时间线开发成本的判断。[.NET 支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)、[WPF 概览](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/)、[NotifyIcon](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon?view=windowsdesktop-10.0)、[Microsoft.Data.Sqlite](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/)。

### 建议的交付方式

当前电脑为 x64，第一版建议交付包含运行时的 Windows x64 程序文件夹；运行者无需另外安装 .NET SDK 或 .NET 运行时。文件夹放在固定位置，登录自启指向其中的可执行文件；不先增加安装器、更新器或多架构发布。开发阶段仍需 SDK，随程序携带的运行时补丁需由后续程序版本更新。[.NET 发布说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/)。

## 验收场景

1. 编辑器 10 秒 → 微信 2 秒 → 编辑器 10 秒：三个片段均存在，累计编辑器 20 秒、微信 2 秒。
2. 同一浏览器窗口切到不同标题：产生新片段，浏览器汇总连续累计；相同状态重复通知不产生空片段。
3. 阅读文章 20 分钟没有输入：仍计入浏览器；后台音乐不计时，双屏只计当前激活窗口。
4. 手动暂停 → 锁屏 → 解锁：仍手动暂停；睡眠 → 唤醒但仍锁屏：仍不计时；自动停止条件均解除后读取实际前台并恢复。
5. 会话灭屏停止计时，亮屏且解锁后恢复；多显示器和 Modern Standby 场景需实机核验。
6. 异常退出后重启：只计到最后可靠保存的终点，缺口显示未记录，不延续此前软件或停止原因。
7. 23:59–00:01 的片段：两天各累计 1 分钟；每日时间条、日志和软件汇总一致。
8. 拖选范围只筛选相交日志，全天汇总保持全天口径；时间条与日志互相定位，缩放后仍能查看 2 秒片段。
9. 登录后开始采集，关闭主窗口仍继续；显式退出停止，重复打开程序不重复计时。
10. 删除前一天不误删今天；删除今天后旧片段不会重新生成已删内容，未来活动继续记录。
11. 身份或标题读取失败时有可解释的记录；数据库不可写时提示异常，已有数据保留且不补造失败期间的使用。
12. 断网后采集、回看与删除均可用；日志和主要控件可用键盘操作，状态含义不只依赖颜色。

## 决策与限制

计时口径的取舍见 [0001 前台使用计时边界](adr/0001-foreground-usage-boundary.md)，术语见 [GLOSSARY.md](../GLOSSARY.md)。

Windows 提供前台事件与标题接口，但标题可能为空，内容变化也不保证对应标题变化。标题通知、打包应用身份、锁屏／唤醒／灭屏和权限受限窗口均需实施时验证。已保存的窗口标题不保证还原浏览器 URL、网页正文或所有内部页面切换。系统时间回拨和时区切换后的历史裁切不在第一版的正确性承诺内。
