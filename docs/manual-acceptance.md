# FocusOn 桌面人工验收清单

本文提供 W01–W10 的操作步骤，**所有勾选框初始均为未执行**。自动化测试、编译和静态审查不能代替这些结果。实际已有证据见 [实施与验收记录](../.scratch/focuson/verification.md)；完成操作后记录环境、结果和限制，再由维护者汇总。

历史实施阶段用户曾按 Escape 停止界面自动化。2026-10-10 当前工作副本接续时已完成构建、66 项自动化测试和重新打包，但 Windows 界面工具 native pipe 缺失，重试及重置后仍无法连接；本轮没有启动程序、操作桌面或执行硬件测试。后续步骤可在工具恢复后接续，或由用户人工进行。

## 准备隔离环境

1. 使用 Windows 11 x64，把交付文件夹完整放到固定位置，不只复制 `FocusOn.exe`。以下以 `C:\Apps\FocusOn\FocusOn.exe` 为例；执行前改成实际路径。
2. 建议在没有正式 FocusOn 实例的测试会话或测试 Windows 用户下验收，避免混淆两个托盘。单实例按数据目录区分；所有验收命令都必须带同一个隔离 `--data-dir`。若另有正式实例，不操作其托盘或数据。
3. 在 PowerShell 创建独立测试目录，然后启动交付程序。保留下面的变量，后续每次启动都使用同一个 `$testData`，不要双击没有参数的程序：

```powershell
$focusOnExe = 'C:\Apps\FocusOn\FocusOn.exe'
$manualRoot = Join-Path $env:LOCALAPPDATA ('FocusOn-Manual-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
$testData = Join-Path $manualRoot 'data'
New-Item -ItemType Directory -Path $testData -Force | Out-Null
& $focusOnExe --data-dir $testData
```

4. 确认隔离目录中生成 `focuson.db`；SQLite 运行时还可能生成 `focuson.db-wal`、`focuson.db-shm`。正式目录 `%LOCALAPPDATA%\FocusOn` 不用于这些步骤。测试标题使用自建内容，不打开私人历史进行删除或故障测试。
5. 用纸笔或另一台设备记时，记录切换、停止、退出、重启的本地时刻，避免电脑上的计时窗口改变前台归属。准备两个普通软件、同软件的两个窗口及可改变标题的窗口。播放测试音频可使用本地文件。
6. 记录 Windows 版本、程序版本/提交、时区、屏幕数、Windows 缩放、是否支持 S3 或 Modern Standby，以及测试目录。全程保持正常系统时间和同一时区；跨日检查等待真实午夜，不修改系统时钟来制造数据。

**计时口径：**只有激活窗口累计前台使用时长；窗口可见、后台播放或运行不等于前台。没有键鼠输入仍计时，不能把结果解释为注意力。每次打开 FocusOn 或操作任务管理器也会形成它们自己的前台片段。显示取整不等于底层精度；详情中的实时终点不证明尾段已保存。

## W01：前台切换、标题与短片段

- [ ] 在软件 A 保持激活约 10 秒，切到 B 约 2 秒，再回到 A 约 10 秒。打开回看检查日志：A→B→A 应是独立片段，短暂 B 应保留，不能把两段 A 合成一段跨过 B。以详情实际时刻核对手工记时，人工切换不要求恰好 2.000 秒。
- [ ] 在同一软件的两个独立窗口间切换；即使标题相同，也应分段。两个窗口使用同一稳定软件身份汇总。
- [ ] 在当前窗口中切换浏览器本地页面/标签或编辑器文档，使标题实际变化。标题变化应形成新片段；详情应显示完整新标题。
- [ ] 让另一个未激活窗口改变标题，同时让 A 保持前台。可用自建本地网页的定时 `document.title` 变化，不切过去观看；A 不应被这个后台变化分段。
- [ ] 同一窗口及标题不变，静读至少 20 秒并跨过多个五秒检查点。时长应增长，不应每五秒生成一条新使用片段，也不应因没有输入自动停止。
- [ ] 记录窗口切换/标题通知是否漏失或延迟。五秒补查能校核当时窗口，不能重建漏掉的中间活动；发现缺口或错误必须写出实际操作和时刻，不能凭逻辑测试判通过。采集故障已有提示时应显示异常/未记录，不能继续猜测旧软件。

## W02：普通、权限受限及打包窗口

- [ ] 激活普通程序，核对软件名称、完整标题和身份汇总。关闭后重开，同软件应继续归入同一软件汇总。
- [ ] 人工打开一个以管理员权限运行的测试程序，保持前台约 10 秒。可确认窗口但身份不可读时应显示“未知软件”，仍保留可确认的使用时间；标题不可读时显示“标题不可用”，不能因字段失败把整个片段丢掉。
- [ ] 激活至少一个 Windows 打包应用，记录具体应用及版本。软件可被正确解析，或明确显示未知；不能把未解析的宿主进程猜成实际应用。
- [ ] 若测试程序均可读，没有触发权限/标题失败，则相关回退子项记“未覆盖”，不能把正常窗口结果推广到受限窗口。

## W03：双屏、后台播放与自身记录

- [ ] 有双屏时将 A、B 分别放在两个屏幕，保持同时可见并交替激活，各约 10 秒。任何时刻只能归给一个前台窗口；另一屏可见窗口不应同时累计。
- [ ] 让本地音乐/视频在后台播放，A 保持激活约 20 秒。后台播放器不能因播放而累计这段软件时长。
- [ ] 激活 FocusOn 约 10 秒，再切走。FocusOn 自身应按相同规则记录；检查自身标题里的回看日期变化是否形成合理标题边界。
- [ ] 单屏环境将双屏子项记“不适用：单屏”；后台播放和自身记录仍分别执行。

## W04：锁屏、睡眠、灭屏及条件重叠

这些步骤需要人工操作物理系统。预先记下边界时刻，返回后再看历史；不要用伪造通知或改时钟代替。可用 `powercfg /a` 查看硬件支持的睡眠状态。

- [ ] A 前台约 10 秒后按 Win＋L，等待约 20 秒再解锁。锁屏范围应是带原因的停止计时区间，不归给 A；解锁后读取实际当前前台，不沿用旧标题。
- [ ] 先手动暂停，再锁屏并解锁。恢复到桌面后仍应显示暂停，软件汇总不因解锁增长；只有主动继续且其他停止条件已解除才恢复。
- [ ] 从 Windows 电源菜单进入睡眠，等待约 20 秒，唤醒。若唤醒后仍锁屏，应继续停止，直至解锁和屏幕亮起。睡眠时间不应归给此前的软件。
- [ ] 测试正常计时中的整会话灭屏/亮屏，可暂时设置系统屏幕超时且把睡眠超时设得更长。灭屏应停止，亮屏后仍须满足解锁、未睡眠、未手动暂停等条件。完成后恢复原系统电源设置。
- [ ] 双屏时只关闭一台显示器，另一台保持亮且可交互；这不应自动等同整个会话灭屏。再检查整会话屏幕关闭的情形。
- [ ] 支持 Modern Standby 的设备分别验收实际进入、唤醒和恢复边界；不支持则记“不适用”并附 `powercfg /a` 结果。本项目当前测试机器仅确认支持 S3，不能推断 Modern Standby 兼容性。
- [ ] 重叠原因主显示顺序为手动暂停→睡眠→锁屏→灭屏；主要原因改变可分段，所有这些区间都不计入软件汇总。正常系统状态已全部恢复后，观察能否恢复到当时实际前台。

## W05：关窗、托盘、单实例、退出与登录

- [ ] 关闭主窗口，确认托盘仍在。激活 A 约 15 秒，从托盘打开回看，应有隐藏期间的 A 使用片段；重复打开回看不应造成双份片段或重复时长。
- [ ] 分别从托盘暂停、继续，再与主窗口按钮交替操作。两处应控制同一状态，并显示实际暂停/继续结果；自动停止未解除时点击继续也不能开始软件计时。
- [ ] 主窗口隐藏时，再运行 `& $focusOnExe --data-dir $testData`。应定位已有主窗口，托盘和采集写入者均只有一个；重复启动不应使时长翻倍。
- [ ] 从托盘明确退出，确认托盘消失、隔离进程结束。等待约 15 秒再用同一参数启动，退出期间是未记录，不能补给退出前的软件。正常退出前最后可信终点应保留；保存失败则必须显示失败，不能报告已全部保存。

正式普通首次启动会自动设置当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `FocusOn` 值，内容为带引号的绝对程序路径加 `--startup`；没有自启开关界面。`--startup` 隐藏启动驻留托盘，`--data-dir` 隔离启动跳过这项注册；组合参数按 `--startup --data-dir <目录>` 顺序同时提供隐藏和隔离。以下只添加另一名称的 QA 入口，不启动正式数据目录，也不覆盖正式 `FocusOn` 值。

- [ ] 关闭隔离实例后，用上面保留的变量创建一次隔离登录入口。若已有 `FocusOn-QA` 值，应先保留/处理原配置，不能直接覆盖：

  ```powershell
  $qaRunKey = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'
  $qaEntryName = 'FocusOn-QA'
  $qaExistingKey = Get-Item -LiteralPath $qaRunKey -ErrorAction SilentlyContinue
  if ($null -ne $qaExistingKey -and $qaExistingKey.GetValue($qaEntryName, $null) -ne $null) {
      throw 'FocusOn-QA 已存在，请先确认原配置，不覆盖。'
  }
  if ($null -eq $qaExistingKey) { New-Item -Path $qaRunKey -Force | Out-Null }
  $qaCommand = '"' + $focusOnExe + '" --startup --data-dir "' + $testData + '"'
  New-ItemProperty -LiteralPath $qaRunKey -Name $qaEntryName -Value $qaCommand -PropertyType String | Out-Null
  ```

- [ ] 注销再登录：隔离入口应开始采集并隐藏驻留托盘，主窗口不应闪现；从托盘可打开回看。确认仍写入 `$testData`。记录实际登录到启动的延迟，这段不能被补成软件活动。手动运行组合参数可以另测隐藏启动，但不能代替真实注销/登录验收。
- [ ] 验收后删除本次 QA 入口（重新开 PowerShell 时也可使用下面的固定键名）：

  ```powershell
  Remove-ItemProperty -LiteralPath 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name 'FocusOn-QA'
  ```

- [ ] 记录固定路径、登录流程、注册值/移除及隐藏启动各子项的实际结果；没有执行的子项保留待验收状态。QA 登录不会自动设置正式 `FocusOn` 注册值，正式首次启动注册行为与 QA 登录结果应分别记录。

## W06：异常终止、可信尾段与真实写入故障

**异常终止与重启：**

- [ ] 先正常采集至少 20 秒，让已有数据成功保存；在 A 中保持窗口及标题不变。任务管理器“详细信息”显示命令行后，核对目标进程确实使用 `$testData`，记录 PID 及终止时刻，人工结束该隔离进程。不要结束其他用户进程或正式实例。
- [ ] 等待约 15 秒，以同一参数重启。以前成功保存的数据应仍在；最近检查点之后尚未保存的尾段及停机范围应显示未记录，不能延长最后一个软件。正常调度时五秒检查点意味着可能丢失约五秒内的尾段；记录实际最后可信终点与终止时刻差值，超出则记录实测情况，不能拿崩溃前的实时显示当落盘证据。
- [ ] 再正常采集、退出、重启一次。新的活动可继续保存，未记录范围不能在下一次检查点被旧软件或旧停止原因填回。

**运行中写入故障：**需要用户已有的 SQLite 工具，可对上述隔离数据库保持事务；没有工具则此子项仍待验收。该工具只用于故障验收，运行 FocusOn 本身不需要它。

1. 先正常采集至少 20 秒。用 SQLite 工具打开 `$testData\focuson.db`，保持工具连接，在同一连接执行：

   ```sql
   BEGIN IMMEDIATE;
   ```

2. 让事务保持至少 15 秒，期间在 A/B 间切换以触发保存，再打开 FocusOn 查看状态。预期明确提示记录异常/不能可靠保存；此前成功记录仍可回看，失败事务不应留下半次切换，也不能声称新增尾段已经保存。
3. 在保持锁的同一连接执行并关闭连接：

   ```sql
   ROLLBACK;
   ```

4. 等待一次检查点并切换软件，检查恢复后的新增活动及未记录范围。再明确退出、重启检查：成功历史仍在，故障范围不归给旧软件，不被恢复后的检查点填满。

- [ ] 写锁步骤结果已记录，包含错误文字、持锁/释放时刻及恢复情况；若工具自动提交而未持有写锁，应记“未触发”，不是通过。
- [ ] 另测启动目录不可用：先退出隔离实例，在 `$manualRoot` 下创建一个普通文件，把该文件路径传给 `--data-dir`。应明确提示不能开始记录，并退出，不能静默切换到正式目录。此检查不能代替运行中的写入故障。

## W07：时间线、范围、缩放与日志联动

- [ ] 10 票：默认“记录范围”从当天第一条可确认的记录铺到最新终点，连续记录时增长；切换“24h”显示真实本地日边界，切回恢复记录范围。缩放/平移后等待刷新应保持窗口，“重置视图”恢复所选模式。三行为使用/停止/计时，未记录在使用行斜纹，选择范围外的未记录日志应切到 24h 显示。
- [ ] 首行空标题不能开始；输入测试标题后开始，出现累计 HH:mm:ss、暂停/停止，标题不再可编辑。暂停不增长，继续重新增长，停止保留日志并回到可输入新标题。搜索标题、选择计时条、拖选及详情一致；软件汇总不加标题时长。“暂停记录”不暂停标题计时。
- [ ] 标题计时期间锁屏/灭屏应继续，S3 睡眠应暂停，唤醒后仅手动继续；关窗应仍计时，托盘退出/重开恢复为暂停，不补算停机时间。这些标题规则独立于 W04 软件停止规则。真实写锁遇睡眠后保持暂停、释放锁和唤醒不补算睡眠时间。

- [ ] 使用 W01 的长、短片段，检查相同软件各段与汇总标记颜色一致；重启或改看历史日后仍保持同一映射。段宽应遵循真实起止比例，不能把两秒段人为加宽；全天视图中窄段可能小于一像素。
- [ ] 在日志选中约两秒的片段，再点“＋”（放大）。应围绕该记录放大，窄段可看；继续缩放直到最小约两秒显示范围。点“−”（缩小）、“重置视图”应正确恢复所选模式，24h 边界应是所选本地日。
- [ ] 悬停一个可见区段，检查软件/原因、起止到毫秒、UTC 偏移和精确时长；在详情读完整长标题。当前片段应标“进行中”并增长，尾段未保存提示保留。
- [ ] 15 票：同一时间段内左右移动、快速跨段、移出再进入时，提示框稳定跟随鼠标并显示对应记录；在右侧/屏幕边缘不被截断。拖选/平移、折叠时间轴、关闭到托盘和退出时不会遗留弹层。分别检查 Windows/macOS/Linux、100%/150%/200% 和多屏。
- [ ] 15 票：把日志滚到底部，再切换前台软件产生多条新记录，始终显示最新末尾；向上滚动或选择历史项后新增不会抢走位置。再次滚到底部恢复，刷新的同时向上滚动也不会被拉回。筛选/跨日期/详情/语言切换保持原数据和选择口径。
- [ ] 15 票：不同软件的连续段之间有细小间隙，同软件换标题没有额外间隙。放大查看两秒片段，核对精确时间、半开边界点击和全天汇总，不能将视觉间隙误认为未记录时间。
- [ ] 点击时间线区段，应选中并滚动到对应日志；从日志选另一个片段，应同步时间线高亮，并在当前缩放范围外时移到该片段可见位置。
- [ ] 拖选一个范围，记录全天软件汇总，检查日志只留下实际相交的记录。拖选部分片段仍保留该日原日志起止和完整日投影时长；只接触结束边界不算相交，全天汇总不改变。
- [ ] 分别点“取消范围”和“重置视图”：前者恢复全日日志，后者同时恢复当前模式视窗及日志。点击筛选范围外的时间线记录，应取消原筛选并显示所选日志。
- [ ] 选中记录后拖出不含该记录的范围，详情应清空；切换日期也不能留下旧详情。连续刷新约 20 秒时，已有选择、范围和手动滚动位置应稳定，不自动跳到最后一行。
- [ ] Harness 截图版：顶部“时长”开合三行总览，“时段”开合小时分隔，“详情”开合侧栏；点击日志或时间条后自动显示对应完整详情。列表滚动条可拖动，空白轨道点击可翻页，滚轮与键盘仍能滚动。
- [ ] 搜索当前日期的软件或窗口标题，核对日志匹配、时间条淡化和全天汇总不变；无匹配有说明，清空恢复当前范围的日志。搜索软件并拖选上午范围，再点击下午同软件时间条，应只取消范围而保留搜索；点击不匹配的软件才清除搜索。组合筛选、刷新及跨日期结果都不能留下错误详情。
