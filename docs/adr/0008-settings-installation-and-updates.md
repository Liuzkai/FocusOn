# 0008: Settings, installation and explicit updates

Date: 2026-10-14. Status: accepted (explicit user request).

Settings becomes the third page. Move language from the shared header into Appearance, alongside saved Dark (existing default) and Light choices. High contrast wins over either theme. Keep application identity/color assignments and derive readable Light colors without replacing the saved palette. Navigation/presentation changes do not restart the recorder or timer or clear review/statistics scope. About is last and shows the actual assembly version, process runtime and official repository.

Only settings with a useful user decision are exposed: language, theme, login startup and data location. Provide an open-folder shortcut. Do not expose database/checkpoint/sample tuning or automatic record deletion. Login startup retains the previous default on, but a saved off choice removes the owned registration. Explicit --data-dir is isolated: no production startup/pointer changes.

Normal startup resolves an optional `data-location.json` in the platform's original default directory. Invalid pointers fail visibly rather than silently starting an empty history. Language/theme/startup preferences stay with the active data directory, separate from SQLite. Moving requires an explicit save/restart confirmation, a distinct empty destination and exclusive destination lock before shutdown. Stop observers and save the original final boundary, copy SQLite with its backup API (including WAL), run integrity_check, copy/verify remaining regular files, and only then atomically replace the default pointer. Do not merge or overwrite data, follow links inside the copied tree or delete the source. Failures keep the old pointer and reopen the original directory. A running title timer pauses at shutdown. The original directory is an archival backup; old app versions cannot follow the new pointer and must not be used to merge divergent records. Isolated relocation restarts with the new --data-dir and never writes a production pointer.

Updates are manual. Check only the official public stable latest endpoint, on click, with bounded responses/timeouts and explicit errors. Do not upload records or opt users into background network checks. Ignore drafts/prereleases and versions no newer than the installed assembly. Match OS/native architecture and exact official asset URLs. Windows downloads a per-user installer with strict size, checksum filename, SHA256 and optional GitHub digest agreement, refuses untrusted redirects and damaged content, then saves/exits before starting the installer. Linux/macOS provide the matching official download and manual replacement instructions. TLS/checksums provide transport/integrity; they do not establish Authenticode/Developer ID trust.

Build Windows Setup.exe through pinned Inno Setup 6.5.4 on each standard native Windows runner, using the already verified self-contained directory. Lowest privileges, current-user program/shortcuts, architecture gates, integrated icon, optional desktop shortcut, Restart Manager and no forced termination; uninstall only program files and the matching owned startup entry, leaving data/settings/default redirect. Native install/installed executable/reinstall/uninstall and unchanged synthetic SQLite/settings checks gate attachment. Keep portable ZIPs. Retain Inno's upstream license in addition to all original MIT/third-party notices. Windows installers are unsigned until separate signing credentials are configured.

The change uses fresh v0.1.7 source/tag/draft, preserving all previous releases and tags. Six native runners, regressions, packaging and installer evidence gate draft upload; no ordinary push makes releases public. Existing explicit publication guards additionally require the four installer/checksum assets for version 0.1.7 onward. Mac trust policy remains ADR 0005: no unsigned/unnotarized Mac Release asset or formal readiness claim.
