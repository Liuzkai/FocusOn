# 03: 异常停止或保存失败后只展示可信记录，并明确缺口

**What to build:** 用户可以看到记录是否可靠。异常终止、数据库不可写、采集故障或程序未运行后，只保留成功保存的范围；重新启动或故障恢复后的缺口显示未记录，时钟/时区异常有明确提示。

**Blocked by:** 02：暂停及系统停止时不计时，并在全部条件解除后恢复

**Status:** closed

## Acceptance criteria

- [x] 在现有检查点和原子边界保存基础上，成功保存终点成为可信范围；进行中实时显示和已经落盘的终点有明确语义，检查点之间未保存尾段允许丢失但不能伪造已保存。
- [x] 异常终止后重开相同数据库，仅恢复成功提交数据；最后可信终点与恢复之间属于未记录，不能补给旧软件或旧停止原因；恢复重新读取当前系统状态及前台窗口。
- [x] 程序未运行、已知观测故障和无法确认前台的范围公开为未记录；没有记录可确认的活动时不推测使用或停止原因，也不宣称能检测所有静默遗漏的 Windows 通知。
- [x] 实际 SQLite 写入/事务失败时保留已成功历史、公开记录异常并停止声称可靠记录；失败事务不留下半次切换。故障解除后的采集从新的可信观测开始，中间不可信范围不补算。
- [x] 正常关闭的保存与异常停止的恢复走不同验收路径；异常测试丢弃未保存内存，不借用正常退出或清理时保存来证明崩溃恢复。
- [x] 检测系统 UTC 跳变（包括回拨）或时区变化并提示，已保存历史不被静默改写；不新增异常后历史日期映射与裁切正确性承诺。
- [x] 用真实临时 SQLite 执行 T07、T12、T13。写失败采用真实写锁或不可写存储等受控故障，不用假数据库或内部调用次数验收。
- [x] 记录 W06 的实际杀进程、写入故障和重启结果，包含已保存范围、未保存尾段损失和用户可见错误；未知/不可复现硬件限制明确记录。
