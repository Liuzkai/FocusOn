# FocusOn 第一版开发规格

Status: ready-for-agent

用户要求按已提出的任务拆分逐项实施，采用记录会话与真实 SQLite 的主要自动化边界；Windows 观测和界面另做实机验收。产品行为沿用已确认设计。

## Problem Statement

用户需要知道自己一天中哪些软件处于前台、各软件累计使用多久，以及不同时间切换到了什么窗口。仅有软件总时长无法回忆活动顺序，单纯记录激活时间点也无法解释持续时间、停止计时和采集空缺。

工具面向个人的一台 Windows 11 电脑。记录必须离线可用，口径可解释：前台使用时长是窗口激活状态的度量，不代表人的注意力或真实工作时长。

## Solution

建立本机运行的桌面工具：在用户登录后开始采集，将前台窗口及标题变化转换为有起止时间的使用片段，保存到本地；关闭主窗口后通过托盘继续运行。手动暂停、睡眠、锁屏和会话灭屏形成停止计时区间，无法确认的采集范围形成未记录区间。

回看页面提供日期选择、当天各软件前台使用时长汇总、按真实持续时间比例绘制的横向使用时间线、日志列表与详情。时间条和日志联动，支持拖选范围、缩放和恢复全天。

2026-10-10 用户截图版 UI 补充：采用 DeepSeek Harness 的深色紧凑 Toolbar、三行总览、时段分隔和彩色标签日志；使用/停止/未记录保留 FocusOn 语义。允许当前日期软件/窗口标题搜索，仅筛选日志与淡化时间条，不改变全天汇总；不增加跨日检索。详情按选择展开，顶部控件可开合总览、时段分隔和详情。具体要求见 09 票与 `docs/ui/focuson-review.md`，该补充优先于下文最初布局及搜索范围描述。

本规格包含已确认的产品行为、建议工程基线和验收边界。它不要求先搭建通用框架，也不引入其他平台或联网服务。

## User Stories

1. 作为 Windows 11 用户，我希望在个人电脑上使用工具，以便自动记录每天的软件使用过程。
2. 作为本机用户，我希望断网时仍能记录、回看和删除，以便记录不依赖外部服务。
3. 作为本机用户，我希望数据保存在当前 Windows 用户的本地应用数据目录中，以便活动记录由自己管理。
4. 作为本机用户，我希望登录 Windows 后自动开始采集，以便减少每天手动启动的操作。
5. 作为本机用户，我希望关闭主窗口后仍继续记录，以便回看窗口不会影响后台采集。
6. 作为本机用户，我希望通过托盘打开时间线、暂停、继续和退出，以便控制采集状态。
7. 作为本机用户，我希望明确退出时保存当前片段并停止采集，以便退出含义清楚。
8. 作为本机用户，我希望重复打开程序只显示已有实例，以便使用时间不会重复累计。
9. 作为本机用户，我希望时间归属当前前台窗口，以便统计口径与激活的软件一致。
10. 作为本机用户，我希望后台音乐和另一个未激活窗口不累计时长，以便同时可见或运行不被误当成前台使用。
11. 作为本机用户，我希望 FocusOn 自身也按相同规则记录，以便全部前台活动采用一致口径。
12. 作为本机用户，我希望每条使用片段包含软件名、窗口标题、开始时间、结束时间和持续时长，以便理解当时的上下文。
13. 作为本机用户，我希望前台窗口切换形成新片段，以便回看软件和窗口之间的切换。
14. 作为本机用户，我希望当前前台窗口标题变化也形成新片段，以便回看浏览器标签和编辑器文档的变化。
15. 作为本机用户，我希望同一软件的不同片段合并为软件累计时长，以便同时看到总量和明细。
16. 作为本机用户，我希望两秒的短暂切换也被保留，以便切换路径完整。
17. 作为本机用户，我希望相同窗口与相同标题的重复通知不生成额外片段，以便日志不含虚假的切换。
18. 作为本机用户，我希望没有键鼠输入时仍累计前台使用时长，以便静读文章和看视频也能计入。
19. 作为本机用户，我希望手动暂停立即停止计时，并仅由自己主动继续，以便暂停不会被解锁或亮屏意外取消。
20. 作为本机用户，我希望睡眠、锁屏或会话灭屏期间不累计软件时间，以便这些明确停止状态有独立解释。
21. 作为本机用户，我希望停止计时区间显示具体原因，以便区分手动暂停、睡眠、锁屏和灭屏。
22. 作为本机用户，我希望自动停止条件全部解除后才恢复计时，以便单个唤醒或解锁事件不会过早恢复。
23. 作为本机用户，我希望恢复时记录当时实际的前台窗口，以便不会把恢复后的时间继续归给旧软件。
24. 作为本机用户，我希望程序未运行或采集故障的时间明确显示未记录，以便空缺不会被推测补算。
25. 作为本机用户，我希望异常停止后只保留已经成功保存的范围，以便未确认的尾段不会伪装成完整历史。
26. 作为本机用户，我希望软件身份或标题读取失败时仍保留可确认的使用时间，并显示未知软件或标题不可用，以便记录失败有可解释的结果。
27. 作为本机用户，我希望数据库不可写时明确看到记录异常，以便知道工具已经无法可靠保存新的活动。
28. 作为本机用户，我希望默认看到今天并能选择历史日期，以便回看不同日期的活动。
29. 作为本机用户，我希望当天软件汇总按累计时长排序，以便快速了解时间主要花在哪里。
30. 作为本机用户，我希望同一软件在时间条上保持固定颜色，以便快速识别其各次出现。
31. 作为本机用户，我希望区段长度反映真实持续时间，以便直观比较不同活动的时间。
32. 作为本机用户，我希望当前片段标注进行中并持续延长，以便了解正在发生的使用。
33. 作为本机用户，我希望悬停显示软件名、精确起止和时长，详情显示完整标题，以便检查具体片段。
34. 作为本机用户，我希望点击时间条或日志都能定位同一记录，以便在整体和细节之间切换。
35. 作为本机用户，我希望拖选范围仅筛选相交的日志，全天汇总仍表示全天，以便筛选不会改变统计口径。
36. 作为本机用户，我希望放大、缩小并恢复全天视图，以便既查看两秒片段又浏览整天活动。
37. 作为本机用户，我希望停止计时区间与未记录区间有文字和视觉区别，以便不会把已知停止原因与采集故障混淆。
38. 作为本机用户，我希望跨午夜片段在每天视图中只显示该日部分，以便日志、时间条和软件汇总一致。
39. 作为本机用户，我希望通过键盘操作日期、日志选择、详情和缩放，以便主要功能不依赖鼠标或颜色辨认。
40. 作为本机用户，我希望记录长期保留且不自动清理，以便由自己决定保存多久。
41. 作为本机用户，我希望按天删除前明确看到日期和范围并确认，以便避免误删其他日期。
42. 作为本机用户，我希望删除跨日记录时保留另一日部分，以便按天删除真正遵守日期边界。
43. 作为本机用户，我希望删除今天后继续记录未来活动且不会把已删时间写回来，以便删除与持续采集可以共存。
44. 作为本机用户，我希望删除后的范围显示为没有可用记录，以便不会被重新解释为采集故障或被自动补回。
45. 作为本机用户，我希望只采集必要的软件与窗口元信息，不另行采集截图、正文、浏览器网址或键盘输入内容，以便控制活动记录的范围。
46. 作为本机用户，我希望运行交付程序时不需要安装开发工具，以便在固定位置启动后即可使用。

## Implementation Decisions

### 工程基线与职责

- 采用已确认设计中的最小工程方案：C#、.NET 10、WPF、WinForms 托盘和本地 SQLite。SQLite 通过 Microsoft.Data.Sqlite 使用，不引入 ORM。
- 桌面采集和回看界面属于当前用户会话中的一个进程。生产代码先保持一个项目，允许必要的测试载体；不为测试额外建立通用架构层。
- 三项职责是 Windows 状态观测、记录会话与持久化、每日回看展示。界面依赖面向回看的结果，不自行实现第二套计时或软件汇总规则。
- Windows 观测是外部事实入口，用户暂停、继续和删除是控制入口。记录会话负责维护唯一计时归属、写入可信范围并向回看提供片段、汇总和状态。

### 使用片段与软件归属

- 已解析的软件使用稳定的软件身份汇总，优先依据规范化可执行文件路径；PID 和窗口句柄只用于当前采集，不是跨启动的软件标识。
- 片段边界由前台窗口身份或当前前台窗口标题变化触发。同软件不同窗口即使标题相同也分段；同窗口标题变化也分段。后台窗口的标题变化不影响当前前台片段。
- 相同窗口和相同标题的重复通知保持当前片段，不产生空片段。保留所有实际短切换，不按时长过滤或合并跨越其他软件的片段。
- 能确认前台窗口但软件身份读取失败时保留使用时间并显示未知软件；已知软件的标题为空或读取失败时显示标题不可用。完全无法确认前台的范围属于未记录。
- 软件名称可使用进程名兜底；打包应用无法解析时不能把宿主进程猜成实际软件。
- 无键鼠输入不是停止条件，不采集输入内容，也不通过输入频率推断注意力。

### 状态边界

- 手动暂停、睡眠、锁屏和会话灭屏均结束软件片段，并形成停止计时区间。
- 恢复需同时满足采集可用、未手动暂停、会话已解锁、未睡眠、屏幕已亮。恢复必须重新读取当前窗口。
- 手动暂停状态独立于自动停止条件；在同一采集会话中，解锁、唤醒或亮屏不能清除手动暂停。
- 已知停止原因重叠时，显示顺序为手动暂停、睡眠、锁屏、灭屏。主要显示原因改变时分段，任何停止原因均不参与软件时长汇总。
- 会话显示状态用于判断灭屏，仅关闭多显示器中的一台不直接等同于整个会话灭屏。
- 程序未运行或采集不可信的范围不沿用此前的软件或停止原因解释，显示为未记录。手动暂停跨进程是否保留没有已确认要求，本规格不将其新增为产品承诺。

### 时间与数据

- 正常系统时间连续且时区不变时，区间含开始、不含结束；相邻片段共享边界且互不重叠。
- 存储 UTC 起止时刻和已确认持续时长，持续时长由单调时间累计。每日回看使用本地日期边界，软件汇总只来自使用片段。
- 一个区间表作为基本存储，包含记录标识及采集顺序、区间类型、起止时刻、持续时长、软件身份与名称、窗口标题。软件汇总由查询产生，避免维护重复汇总副本。
- 当前片段的已保存终点是最近成功保存的可信范围；进行中的实时显示可以继续延长，但不等于全部尾段已经落盘。
- 软件片段有软件身份与标题字段；停止原因和未记录区间不伪造这些值。
- 系统时钟回拨或时区变化须识别并提示，不能静默重写历史；这些异常后的时间轴映射和历史日期裁切不属于第一版正确性承诺。

### 观测、保存与恢复

- 前台切换主要由系统前台事件捕获；当前前台窗口的名称变化用于标题边界。保持消息循环、事件顺序、回调生命周期并防止重入。
- 启动和每次恢复主动读取当前前台及系统状态，避免等待下一次切换才开始。
- 低频检查点用于校核当前窗口及标题并保存可信终点，初始工程建议为五秒；它不替代事件采集，也不是用户可配置的新功能。
- 切换、停止计时和正常退出时立即保存边界，相关更新和插入通过事务保持一致。
- 重新打开已有数据时，只认可成功保存的范围。检查点之间的未保存活动可能丢失；之后的缺口不能补给最后一个软件或旧停止原因。
- 写入失败保留此前成功数据，公开状态提示记录异常并停止声称可靠记录。恢复后的不可信范围标为未记录，事务失败不留下半次切换。

### 日期、筛选和删除契约

- 日期查询提供该日期范围内的使用片段、停止计时区间、未记录范围、全天软件汇总和当前记录状态。跨日片段按日期范围裁切，汇总使用同一裁切结果。
- 范围筛选在每日投影上选择有实际相交部分的日志；仅接触片段结束边界不构成相交。范围筛选不再次裁短日志起止时间，也不改变全天汇总。
- 日期裁切和范围筛选是不同操作：跨午夜日志显示当日部分的边界，拖选范围保持这份当日日志的起止信息。
- 按天删除向用户明确展示日期和范围，确认后事务执行。跨日记录仅删除该日部分，其他日期仍可回看。
- 删除今天先结束开放片段，再删除已有范围，从删除完成后的时刻继续记录当前状态。删除不改变手动暂停或自动停止条件，只有满足恢复条件时才开始使用片段。后续检查点保存及重启不能把已删使用或标题补回。
- 删除成功后的空缺显示为没有可用记录，不标成采集故障。存储方式由实现满足此公开契约，不在本规格额外规定第二张表或历史重建功能。

### 界面、运行和交付

- 页面顺序为日期与记录状态、全天软件汇总、横向使用时间线、时间顺序日志与选中记录详情。
- 默认今天，可选历史日期；没有可用数据时给出明确说明。软件汇总按累计前台使用时长排序。
- 时间条长度反映真实持续时间，同一软件颜色固定；短片段不人为扩大计时宽度。放大、缩小和恢复全天支持查看短片段。
- 时间条和日志双向选择、定位，悬停呈现软件名、精确起止与时长，详情显示完整标题。当前片段标为进行中。
- 停止计时用有原因的灰色区段，未记录使用不同纹理和文字；主要控件有键盘操作，信息表达包含文字。显示取整不改变底层统计值。
- 日志使用虚拟化展示，避免长历史一次创建全部界面行；日志时刻显示到秒，详情显示更精细时长，显示取整不改变底层统计值。
- 登录自启驻留托盘，关闭主窗口继续采集；明确退出保存终点并停止；重复启动定位已有实例。
- 登录自启的延迟仍属于未记录，不补造登录后但采集前的活动。
- 记录长期保存在当前 Windows 用户的本地应用数据目录中，不自动清理。仅采集软件、标题、起止和时长等必要元信息；公开标题本身可能包含文档名、网页名或网址，不另外读取浏览器地址。
- 初始交付面向 Windows x64，建议使用携带运行时的程序文件夹，放在固定位置供自启引用。开发需要匹配 SDK，运行交付程序不要求开发工具；运行时补丁由后续程序版本更新。

## Testing Decisions

### 拟采用的主要自动化边界

集中在记录会话这一处应用行为边界：输入受控的前台窗口观测、标题变化、系统停止状态、UTC／单调时间，以及暂停、继续和按天删除操作；经过正式计时和持久化行为，写入真实的临时 SQLite；通过每日回看使用的公开查询与记录状态验证结果。

这个逻辑边界覆盖观测进入后的计时、持久化、每日投影及删除，不要求专门创建通用仓储、事件总线或新的生产项目。Windows 观测替身只提供外部事实，时间可控；数据库使用实际 SQLite，不用假数据库证明保存正确。

好测试验证用户可以观察到的片段、时间归属、原因、汇总、缺口和重开后的数据。测试不绑定私有方法、SQL 文本、内部调用次数、表字段布局或特定类名。

目前仓库仅有设计和配置文档，没有现成代码、测试框架或测试先例。不得声称已经沿用了既有测试，也不得把以下测试计划描述为已运行结果。

### 主要行为矩阵

| 编号 | 输入或操作 | 应验证的公开结果 |
| --- | --- | --- |
| T01 | 编辑器十秒、微信两秒、编辑器十秒 | 三个使用片段；编辑器二十秒、微信两秒；无重叠或空片段 |
| T02 | 同软件换窗口、同窗口换标题、重复相同通知 | 实际变化分段，重复事实不分段，软件汇总合并 |
| T03 | 同一窗口二十分钟无键鼠输入 | 持续累计二十分钟，不生成推测空闲 |
| T04 | 手动暂停后锁屏再解锁；睡眠后唤醒但仍锁屏 | 全部恢复条件满足前不计时，手动暂停保持，恢复读取实际窗口 |
| T05 | 四种停止条件重叠并逐个解除 | 主要原因按既定顺序切换，停止时间不计入软件汇总 |
| T06 | 无法确认前台、未知身份、不可用标题 | 前者未记录；后两者保留可信使用时长并显示回退文字 |
| T07 | 保存检查点后丢弃未保存内存尾段，不走正常退出保存路径，再使用同一数据库启动新会话 | 只保留成功保存范围，缺口不延续旧软件或停止原因 |
| T08 | 二十三时五十九分至次日零时一分 | 两天各一分钟；每日片段、时间条数据和软件汇总一致 |
| T09 | 选择局部时间范围，包括仅接触边界的片段 | 仅返回实际相交日志；日期裁切结果不被再次裁短；全天汇总不变 |
| T10 | 删除历史日，包含跨午夜片段 | 当日范围删除，另一日仍保留；删除不伪装成采集故障 |
| T11 | 删除正在采集的今天，继续保存并重新打开数据；也覆盖暂停期间删除 | 已删使用及标题不回写；未来活动从删除后开始；旧开放片段不复活；删除不解除停止条件 |
| T12 | 真实 SQLite 写入失败、事务失败及恢复 | 成功历史保留、状态异常、失败范围不补算、无半次切换 |
| T13 | 系统 UTC 跳变或时区变化 | 识别并提示，历史不被静默重写；不承诺异常后裁切正确 |

使用独立临时数据库和可控时间，不依赖固定墙上时刻或实际等待二十分钟。SQLite 写入故障可通过实际连接的受控写锁或不可写存储等方式验证，无需新增假的持久化体系。实例重开可证明已提交数据的恢复边界；真实杀进程及系统挂起仍属于实机验收。
